# Brand

**Pip** is Homingbird's mascot and mark: a 16×16 pixel pigeon shaped like a speech bubble, with a
slate-blue body, a tall black eye, and an orange beak and feet. When a note is on its way, Pip carries
a yellow envelope.

| `assets/characters/<id>/<id>-sheet@1x.png`, `@8x.png`, `characters.json` | The 24 built-in profile characters |
| `assets/fonts/` | Inter and Bricolage Grotesque, Open Font License |

`pip-sheet.json` lists 22 states with what each is for. Use the ones your UI needs.

Every file under `assets/brand`, `assets/pip` and `assets/characters` is generated by
`packages/sprites`. Change the pixels there, then run `pnpm --filter @homingbird/sprites assets`
and commit the result. The tests compare every sheet with `packages/sprites/test/golden/`, so an
intended change to the art also replaces those files.

## Logo

Pip followed by lowercase `homingbird` in Bricolage Grotesque ExtraBold with `-0.02em` letter
spacing. Interface text is set in Inter.

## Rules

- Scale Pip by whole numbers only, with nearest-neighbour sampling: `image-rendering: pixelated`.
- Keep two pixels of clear space around the mark, at the mark's own scale.
- Minimum size: 16px for the mark, 96px wide for the full logo.
- Do not stretch, blur, recolour or rotate Pip.

- Animate only what is changing; lists show the first frame, still. With reduced motion, always the
  first frame. Never animate the logo or the app icon.
- Pair every state with words. Animation and color are never the only signal.

An organization that restyles the web client through `theme.css` changes the interface tokens, not
Pip.

## Profile characters

Pip is the brand: the logo, the app icon, onboarding, empty screens and system notices. Members pick a
**profile character** for their avatar: one of 24 built-ins (`pigeon`, `cat`, `dog`, `rabbit`, `bear`,
`fox`, `penguin`, `duck`, `frog`, `owl`, `panda`, `hamster`, `goldfish`, `pufferfish`, `octopus`,
`whale`, `turtle`, `hedgehog`, `pig`, `sheep`, `ladybug`, `bee`, `robot`, `dinosaur`), or one they
make. New members start as `pigeon`, which wears Pip's colors. A character is never the logo, the app
icon or a marketing image.

Every character is Pip's body with another palette and markings, so all 22 states work for every
character. The envelope, badges and other status icons are system art and look the same on all of
them. A character is a `CharacterSpec`:

```json
{
  "version": 1, "base": "bubble-16", "id": "my-otter", "name": "Otter",
  "palette": { "B": "#8A6A52", "D": "#6E523F", "O": "#E7D3BF", "F": "#6E523F" },
  "noFeet": false,
  "marks": [[5, 1, 1, 1, "B"], [10, 1, 1, 1, "B"], [15, 6, 1, 1, "#2E2018"]]
}
```

`palette` keys are body, wing or arm, beak or muzzle, feet and eye; missing keys use Pip's colors.
A mark is `[x, y, w, h, color]` in whole cells of the 16×16 grid.

### Character rules

`validateCharacter` in `packages/sprites` holds these rules. Clients call it for feedback and Dovecote
calls it again before saving.

- **Fixed:** the outline, the eye position, the frames, the 22 states, the envelope and the icons.
- **Zones:** markings anywhere inside the body except the mouth zone (x 11–15, y 8–11): characters
  have no mouths. Outside the body only on the head top (x 2–11, y 0–2), the tail (x 0–2, y 11–15),
  underneath (x 3–13, y 13–15, with `noFeet`), or as single spikes touching the outline (10 at most).
  Never in the status-icon corner (x 12–15, y 0–4).
- **Limits:** 8 colors, 80 marked cells, 16 of them outside the body.
- **Contrast:** the eye 3:1 against whatever is behind it; half the outline visible on Mist and on
  Night; the body clear of the envelope yellow, alert red and sparkle teal.
- **Names:** 1–20 characters, without Claude, Anthropic, Homingbird or Pip. A made character may not
  copy Pip's colors.
- **Content:** no text, logos, flags or symbols in the pixels; no real people and no other companies'
  characters; nothing offensive.

### Making a character

Two ways in, one result:

- **The editor**, for everyone. Start from a built-in or blank; pick six colors, an automatic or set
  eye, and one part per slot (pattern, face, ears, on the head, spikes, nose, tail, underneath).
  Options that would break a rule with what is already picked are disabled, with the reason.
  **Surprise me** makes a random character that passes every rule; the seed comes from the random
  service, so the same seed gives the same character.
- **Ask Claude**, where a model is available. Claude drafts a `CharacterSpec` from
  `packages/sprites/skills/make-character/SKILL.md`, checks it with the same rules, and the draft opens
  in the editor with its markings as a separate layer.

Nothing is saved until the person presses **Use this character**. Model-facing tools may check and
preview a character but never save one.
