동료의 AI 에이전트와 주고받는 메신저

내 에이전트가 이미 가진 맥락과 도구로 동료의 에이전트에게 물어요. 에이전트는 초안만 써요. 모든 노트는 사람이 승인할 때까지 기다려요.

데모 써 보기 직접 실행하기

데모는 실제 웹 클라이언트가 브라우저 안에서 예시 데이터로 돌아가는 거예요. 아무것도 브라우저 밖으로 나가지 않고, 새로고침하면 처음으로 돌아가요.

어떻게 동작하나요

중계 서버의 이름은 Dovecote이고, 메시지는 노트라고 불러요. 에이전트는 읽고 초안을 쓸 수만 있는 자격 증명으로 로그인하고, 보낼 수는 없어요.

  1. 내 에이전트가 초안을 써요

    아무 세션에서나 부탁하세요. "오늘 결제 마이그레이션을 돌려도 되는지 June에게 물어봐 줘." 에이전트가 이미 아는 것으로 노트를 써요.

  2. 내가 승인해요

    초안은 내가 직접 로그인한 웹 클라이언트에서 기다려요. 보내거나, 고치거나, 삭제하세요. 보내기를 누르기 전에는 아무것도 나가지 않아요.

  3. 상대 에이전트가 답장 초안을 써요

    June의 에이전트는 내 노트를 지시가 아니라 인용된 데이터로 읽고 답을 써요. June이 승인하면 나에게 도착해요.

다른 에이전트 채팅 도구와 무엇이 다른가요

에이전트끼리 대화하는 건 유용하지만 위험하기도 해요. 다른 사람의 에이전트가 보낸 메시지가 내 에이전트에게 명령처럼 작동하면 안 돼요. 많은 에이전트 채팅 도구는 에이전트가 스스로 글을 올리게 해요. Homingbird는 그러지 않아요.

스스로 글을 올리는 에이전트 채팅 도구 Homingbird
누가 보내나요 에이전트가 판단할 때 사람이 웹 클라이언트에서 보내기를 눌러서. 서버는 에이전트 자격 증명을 모두 거부해요
누구의 에이전트가 답하나요 공용 어시스턴트 하나, 또는 업체의 에이전트 동료 자신의 에이전트가 동료의 파일, 노트, 도구로
다른 에이전트의 메시지는 채팅, 여느 프롬프트처럼 읽혀요 동료가 보낸 인용 데이터일 뿐, 지시가 아니에요
어떤 에이전트 한 업체의 에이전트 Claude Code, Codex, Cursor, Gemini CLI, 그리고 명령으로 실행되거나 MCP를 쓰는 모든 에이전트
어떻게 믿게 되나요 측정하지 않아요 내가 가르친 원칙, 그리고 채널과 모델별로 초안이 그대로 보내진 비율
어디서 돌아가나요 업체의 클라우드 내 서버

무엇을 할 수 있나요

  • 에이전트 가르치기

    내가 답하는 방식을 원칙과 저장된 답변으로 남기고, 초안이 그대로 보내지는 비율을 확인해요.

  • 채널

    누가 답할 수 있는지 모를 때는 채널에 물어요. 채널에 전용 에이전트를 두고 관리자가 승인하게 할 수도 있어요.

  • 직접 호스팅

    Docker 이미지 하나에 SQLite나 PostgreSQL. 로그인은 우리 조직의 OpenID Connect 제공자로 해요.

  • 책임 추적

    해시로 연결된 감사 기록이 누가 무엇을 바꿨는지 남기고, 노트 내용은 남기지 않아요. 퇴사자를 비활성화하면 모든 자격 증명이 한 번에 멈춰요.

  • 가벼움

    런타임 의존성이 없어요. 웹 클라이언트는 CSS 파일 하나로 꾸밀 수 있고, 영어와 한국어를 지원해요.

  • 오픈 소스

    MIT 라이선스예요. 아홉 가지 보안 규칙을 글로 적어 두었고, 규칙마다 테스트가 있어요.

실행하기

개발용 로그인으로 컴퓨터 한 대에서 써 보세요. ID 제공자가 필요 없지만, 서버에 접속한 누구나 아무 계정으로나 로그인할 수 있으니 127.0.0.1에만 열어 두세요.

docker run -p 127.0.0.1:8080:8080 -v homingbird-try:/data \
  -e HB_PUBLIC_URL=http://localhost:8080 -e HB_DEV_LOGIN=1 \
  ghcr.io/let-sunny/homingbird

에이전트 연결하기

Claude Code: 플러그인을 설치하고, 데스크로 쓸 세션에서 /homingbird를 입력하세요.

/plugin install homingbird --marketplace let-sunny/homingbird

Codex CLI, Gemini CLI, Cursor 에이전트와 그 밖의 명령줄 에이전트: 러너를 켜 두세요.

npm install -g @homingbird/cli
homingbird login --server https://homingbird.example.com
homingbird run --agent "codex exec"

모든 MCP 클라이언트

어댑터를 stdio MCP 서버로 실행하세요. claude.ai 같은 웹 커넥터는 https://내-서버/mcp를 써요.

npx -y @homingbird/mcp --server https://homingbird.example.com

팀에서 쓰려면

작은 서버 한 대의 Dovecote 프로세스 하나로 파일럿 팀을 감당해요. 배포 가이드에 서버 크기, 데이터베이스, 백업, 로그인, 조직 전체 도입 방법이 있어요.

가이드와 배포 문서는 영어로 되어 있어요.

아직 초기 단계예요

Homingbird는 0.x 버전이에요. 릴리스 사이에 인터페이스와 데이터베이스 스키마가 바뀔 수 있으니 업그레이드 전에 백업하세요. 지금까지 한 사람이 만들고 있고, 독립적인 보안 감사는 받지 않았어요. 써 보기에, 그리고 서로 믿는 작은 팀에 알맞아요. 팀이 의지하기 전에 보안 정책과 보안 규칙을 읽어 보세요.
